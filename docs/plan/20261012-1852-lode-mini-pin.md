## Context

Every place this repository takes lode from pinned `docker.io/bkhq/lode:v0.0.1`,
the full image (about 95 MB). All of them only copy `/usr/bin/lode` out of it:
the runtime `Dockerfile` (`COPY --from`), `scripts/ci/sign-release.sh`, the
e2e suites and the two example workflows (`docker create` + `docker cp`).
lode publishes a `-mini` variant of each tag, built on distroless static: the
binary and nothing else, about 3 MB. The newest release is v0.0.3.

`llms.txt` described publishing from GitHub Actions in one sentence and a
link.

## Proposal

- Pin `docker.io/bkhq/lode:v0.0.3-mini` in the `Dockerfile`,
  `scripts/ci/sign-release.sh`, `ci.yml`, the e2e suites (cache directory
  `lode-v0.0.3`) and `examples/publish/`.
- `llms.txt`: a recommended GitHub Actions workflow in full, the image
  variants, and `latest-mini` where the text only copies the binary out.
- `examples/publish/`: note the `-mini` tags; run on `ubuntu-26.04` like the
  repository's own workflows.

## Risks

- lode 0.0.3 could behave differently from 0.0.1 where the e2e suites pin its
  output. Checked by running the suite against the 0.0.3 binary.
- The mini image has no shell. Nothing here runs a command in the image.
- `docker run … bkhq/lode:latest` in `llms.txt` and `examples/hello` stays on
  the full image: that example app is a shell script.

## Scope

`Dockerfile`, `scripts/ci/sign-release.sh`, `.github/workflows/ci.yml`,
`tests/e2e/`, `examples/`, `apps/web/public/llms.txt`, docs.

## Alternatives

- `latest-mini` everywhere: CI and the runtime image would change without a
  commit.
- A second example directory: `examples/publish/` already is the workflow
  example.
